# Antigravity 2.0 界面样式逆向与任务栏透明化技术方案

本文档详细记录了在 **对话「左侧任务栏样式调整」** 中，针对 Antigravity 2.0 桌面端界面的深度逆向分析、选择器定位以及 CSS 遮罩剔除方案。

---

## 一、背景与问题现象

在完成壁纸底图注入后，界面仍然存在两个明显的视觉遮挡问题：
1. **主对话框背景发灰、不透明**：
   在新建对话中央的主输入框呈现一层浅灰色矩形，无法通透展示背后的晨雾森林壁纸。
2. **左侧侧边栏标题/项目列表带有浅灰色半透明背景条**：
   在左侧侧边栏的对话列表项、项目列表项下方，每个条目都有一个矩形遮罩层（系统原生卡片背景色），导致左侧背景被大面积灰白色遮盖，无法呈现纯粹通透的磨砂质感。

---

## 二、逆向分析与 DOM 结构定位

由于 Antigravity 2.0 属于预编译且混淆的 React + Tailwind CSS 架构，直接审查样式不可见，我们通过构建辅助脚本进行了深度逆向探查：

### 1. 主输入框结构探查
* 核心容器选择器：`[data-testid="agent-input-box"]`
* 内部结构：
  - 外层边框层：`.bg-card-border` / `bg-card`
  - 内层输入容器：包含了 CSS 变量 `--card: color(srgb 0.11 ...)`
* 导致不透明的原因：
  Antigravity 内部组件不仅在容器上声明了 background 样式，还在父级或内部子元素上绑定了多个 Tailwind 实用类（`bg-background`, `bg-card`, `bg-muted` 等）。

### 2. 左侧侧边栏条目结构探查
通过探查侧边栏列表项与容器链路，定位到关键层级：
* 侧边栏主滚动容器：`aside`, `[data-testid="conversation-list-sidebar"]`
* 列表项目按钮与链接：
  - 各对话项容器：`button`, `a[href*="/chat/"]`, `div.group`
  - 原生混淆类名：系统在列表项上应用了默认的半透明浅色背景（如 `bg-accent/40`, `bg-muted`, `bg-card/50` 等），形成了一个个灰度不一的长方形色块。

---

## 三、CSS 优化与穿透解决方案

通过将样式精准追加至 [`晨雾森林毛玻璃主题.css`](file:///d:/work/antigravity-background/%E4%B8%BB%E9%A2%98%E6%A0%B7%E5%BC%8F/%E6%99%A8%E9%9B%BE%E6%A3%AE%E6%9E%97%E6%AF%9B%E7%8E%BB%E7%92%83%E4%B8%BB%E9%A2%98.css)，采用了**变量穿透 + 选择器覆盖 + 交互态增强**的综合方案：

### 1. 彻底清除左侧任务栏/侧边栏项目矩形遮罩
```css
/* 彻底清除左侧侧边栏列表项的灰色长方形遮罩层，直接展示底层壁纸 */
aside [role="button"],
aside button,
aside a,
aside [data-testid="conversation-list-sidebar"] [role="button"],
aside [data-testid="conversation-list-sidebar"] button,
aside [data-testid="conversation-list-sidebar"] a,
[data-testid="conversation-list-sidebar"] div[class*="hover:"],
[data-testid="conversation-list-sidebar"] div[class*="group"] {
  background-color: transparent !important;
  background-image: none !important;
  border-color: transparent !important;
  box-shadow: none !important;
}

/* 仅在鼠标悬停(Hover)时给予极其克制柔和的微光反馈，提升操作辨识度 */
aside [role="button"]:hover,
aside button:hover,
aside a:hover,
aside [data-testid="conversation-list-sidebar"] [role="button"]:hover,
aside [data-testid="conversation-list-sidebar"] button:hover,
aside [data-testid="conversation-list-sidebar"] a:hover {
  background-color: rgba(255, 255, 255, 0.08) !important;
  border-radius: 6px !important;
  transition: background-color 0.2s ease !important;
}

/* 针对当前选中的高亮活跃条目 */
aside [data-active="true"],
aside [aria-selected="true"],
aside button[class*="bg-accent"],
aside a[class*="bg-accent"] {
  background-color: rgba(52, 211, 153, 0.16) !important; /* 晨曦青绿微光高亮 */
  border-radius: 6px !important;
}
```

### 2. 主对话框变通透磨砂
```css
/* 主输入框及其嵌套卡片全透明化，透出晨雾背景 */
[data-testid="agent-input-box"],
[data-testid="agent-input-box"] > div,
[data-testid="agent-input-box"] form,
[data-testid="agent-input-box"] textarea,
div[class*="bg-card"],
div[class*="bg-card-border"] {
  background-color: rgba(20, 24, 28, 0.45) !important; /* 降低底色不透明度至0.45 */
  backdrop-filter: blur(12px) !important;
  -webkit-backdrop-filter: blur(12px) !important;
  border: 1px solid rgba(255, 255, 255, 0.12) !important;
}

/* 重置组件内部 CSS 变量，从底层防止纯色遮罩回退 */
[data-testid="agent-input-box"] {
  --card: transparent !important;
  --card-foreground: inherit !important;
  --popover: transparent !important;
  --muted: rgba(255, 255, 255, 0.05) !important;
}
### 3. 会话选中态右侧功能按钮内联渐变黑底穿透
* **问题成因**：侧边栏会话列表项在选中或悬停时，右侧容器（包含 `conversation-kebab`、`conversation-pin-button`、`conversation-archive-button`）自带内联样式：
  `style="background: linear-gradient(to right, transparent 0%, var(--sidebar-secondary) 25%);"`
  在深色模式下，`var(--sidebar-secondary)` 回退为默认的实心纯黑色，导致选中会话后右侧出现突兀的黑色长方形。
* **解决方案**：
  通过 `:has()` 伪类及属性选择器联合覆盖，强制消除容器的渐变与背景：
  ```css
  [data-testid="conversation-list-sidebar"] div[style*="linear-gradient"],
  [data-testid="conversation-list-sidebar"] div[style*="var(--sidebar-secondary)"],
  [data-testid="conversation-list-sidebar"] div:has(> [data-testid="conversation-kebab"]),
  [data-testid="conversation-list-sidebar"] div:has(> [data-testid="conversation-pin-button"]),
  [data-testid="conversation-list-sidebar"] div:has(> [data-testid="conversation-archive-button"]) {
    background: transparent !important;
    background-color: transparent !important;
    background-image: none !important;
  }
  ```

### 5. 避免 Window Controls Overlay (右上角窗口控制按钮) 出现白色/灰色色块
* **问题成因**：
  Electron 在 Windows 平台使用 Window Controls Overlay (WCO) 承载右上角的最小化、最大化、关闭按钮。
  1. **合成层回退**：若在顶层包含 WCO 的庞大祖先容器（如整个右侧内容区）上滥用 `:has()` 并施加 `backdrop-filter: blur(...)`，会导致 Chromium 硬件加速合成器（Compositor）与 Windows DWM 桌面窗口管理器的非客户区亚像素混合失效，促使 Windows DWM 触发回退机制，将右上角控制按钮背景直接渲染为 `#CCCCCC` 灰白色实心方块；
  2. **页面重载（Ctrl+R）生命周期时序脱节**：当用户刷新页面（Ctrl+R）时，Chromium 会重置前端上下文并将 WCO 恢复为原生默认背景。若透明化接口（`setTitleBarOverlay`）仅在插件脚本加载的一瞬间同步执行一次，此时 `preload.js` 异步暴露的 `window.electronNative` 尚未就绪，导致调用静默跳过；且由于缺少后续生命周期重试，右上角就会持续停留在默认的纯白/实灰色状态，造成与样式调整“联动”的假象。
* **解决方案**：
  1. 坚决避免在顶层大容器上使用全局复合 `:has()` 并添加模糊滤镜；
  2. 精准将透明与微光样式限制在具体的 `[data-testid="breadcrumb-segment"]`、`[data-testid="open-editor-single"]` 等目标叶子元素上；
  3. 为 `app-region: drag` 和 `window-controls` 等区域设置显式透明防护，杜绝实心色块污染；
  4. **全生命周期保活守护（`startTitleBarKeeper`）**：在汉化插件中实现多重重试机制（最大重试 30 次，每次间隔 150ms 轮询等待 `electronNative` 就绪）、绑定 `DOMContentLoaded` / `load` / `resize` / `focus` 关键事件，并在启动前 6 秒内维持每 600ms 一次的心跳加固，确保即使多次按 Ctrl + R 刷新，WCO 也必定在毫秒级内自动锁定为带 0 Alpha 的完全透明色（`{ color: '#00000000', symbolColor: '#ffffff', height: 30 }`）。

### 6. Markdown 引用块（`<blockquote>`）深黑底色条消除
* **问题成因**：
  在对话区渲染 Markdown 的 `>` 引用块时，底层组件会解析生成 `<blockquote style="background-color: var(--muted); border-left: 4px solid var(--border); padding: 0.5rem 1rem; ...">`。因其携带内联样式的 `var(--muted)`，在深色模式下回退为纯黑实底色（`color(srgb 0.0861764 ...)`），横向贯穿整个对话气泡宽度，遮挡住半透明磨砂壁纸。
* **解决方案**：
  在主题 CSS 中对所有 `blockquote` 以及带内联背景样式的引用块实施 `!important` 覆盖，取消底色与雾化滤镜，保持绝对纯透明并直显高清壁纸：
  ```css
  blockquote,
  blockquote[style*="background-color"],
  div[data-testid="conversation-view"] blockquote,
  [data-testid*="message-item"] blockquote,
  [data-testid="conversation-view"] [class*="chat-bubble"] blockquote {
      background-color: transparent !important;
      background: transparent !important;
      backdrop-filter: none !important;
      -webkit-backdrop-filter: none !important;
      box-shadow: none !important;
      border-left: 3px solid rgba(52, 211, 153, 0.50) !important;
      border-top: none !important;
      border-right: none !important;
      border-bottom: none !important;
      border-radius: 0 !important;
      color: rgba(255, 255, 255, 0.90) !important;
  }
  ```

## 四、经验总结与避坑要点

1. **Chromium 沙箱协议限制**：
   - 本地前端在 `https://127.0.0.1:...` 域下运行，不能直接引用 `file:///C:/...` 本地图片，否则被浏览器的 CORS / 跨协议沙箱安全机制静默拦截。
   - **最优解**：将壁纸预先转换为 Base64 内嵌在 CSS 中，彻底绕过协议拦截，达到毫秒级瞬间渲染。
2. **Tailwind 嵌套组件的变量穿透**：
   - 很多现代化前端应用广泛使用 CSS 自定义属性（`--background`, `--card`, `--accent` 等）。只修改 `background-color` 有时会被子级变量覆盖；必须结合父级 CSS Variable 重写与 `!important` 组合打击。
3. **Electron Window Controls Overlay (WCO) 与硬件合成层冲突**：
   - 避免在窗口控制按钮下方的大范围容器应用 `backdrop-filter`，防止 DWM 合成失败出现灰色/白色色块回退。
4. **即时调试方式**：
   - 修改 CSS 后无需重启进程，在 Antigravity 窗口直接按 <kbd>Ctrl</kbd> + <kbd>R</kbd> 热重载即可瞬间渲染出最新样式。
